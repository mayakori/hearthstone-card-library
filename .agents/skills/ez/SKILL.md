---
name: ez
description: Use when the user types /ez, or asks for a clearer / "쉽게 설명" rephrasing of something — a complex, technical, or variable-heavy explanation that is hard to follow on first read.
---

호출되면, 일반적인 프로그래머가 이해할 수 있는 수준으로 다시 설명한다. (비전문가용으로 낮추지 않는다.)

**대상:**
- `/ez` (인자 없음) → 직전에 한 복잡·기술적 설명을 더 명확하게 다시 풀어 쓴다.
- `/ez <대상>` → 인자로 받은 개념·용어·코드 동작을 명확하게 설명한다.

**방식:**
- 변수·심볼·코드 식별자를 하나씩 짚어가며 설명하지 않는다. 무엇을 왜 하는지 자연어 단어·개념으로 설명한다. (변수 추적 < 개념 서술)
- 흔한 프로그래밍 용어는 그대로 써도 된다. 프로젝트 고유·생소한 용어만 한 줄로 풀이한다.
- 짧게. 핵심 한두 가지에 집중하고, 디테일보다 "큰 그림"과 "왜 중요한지"를 먼저 전한다.
- 정확성은 희생하지 않는다 — 명확하게 만들되 틀리게 만들지 않는다.

**하지 말 것:**
- 원래 설명에 없던 새 기술 깊이를 추가하지 않는다.
- 단어만 바꿔 같은 내용을 그대로 반복하지 않는다. 실제로 더 명확해야 한다.
- 비유·은유로 바꿔치기 하지 않는다. 개념을 직접 서술한다. (비유는 틀린 그림을 주거나 해석을 한 겹 더 얹는다)
