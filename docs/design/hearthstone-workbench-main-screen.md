# Hearthstone Workbench 메인 화면 설계

- 상태: 메인 화면 승인
- 기준일: 2026-07-24
- 제품 범위: 개인용 데스크톱 카드 탐색·덱 구성 작업대
- 시각 정본: `preview/hearthstone-workbench-foundation.html`
- 반응형 검증본: `preview/responsive-workbench-lab.html`

이 문서는 첫 메인 화면의 구현 기준이다. 컴포넌트별 props, 내부 상태 모델과 테스트 API는 별도 컴포넌트 설계 세션에서 확정한다.

## 1. 화면의 역할

사용자는 한 화면에서 다음 작업을 연속으로 수행한다.

1. 카드 라이브러리를 빠른 속성 또는 고급 논리 조건으로 좁힌다.
2. 카드 이미지를 직접 훑으며 좌클릭으로 덱에 추가한다.
3. 우측 덱에서 구성, 비용 분포와 기본 메트릭을 즉시 확인한다.
4. 덱을 분석하거나 하스스톤 덱 코드를 복사한다.

첫 시선은 카드 라이브러리, 두 번째는 현재 필터, 세 번째는 현재 덱 상태로 향한다. 카드 아트가 주인공이며 앱 표면은 이를 방해하지 않는다.

## 2. 정보 구조

```text
WorkbenchScreen
├─ ResponsivePaneSwitch                  좁은 폭에서만 노출
└─ WorkbenchLayout
   ├─ CardLibraryPane
   │  ├─ LibraryToolbar
   │  │  ├─ ManaMultiSelect
   │  │  └─ CardTypeFilter
   │  ├─ CardLibraryScrollArea
   │  │  └─ CardGrid
   │  │     └─ CardTile × N
   │  └─ FilterDock
   │     ├─ LogicBucket(AND / OR / NOT)
   │     │  └─ FilterClause × N
   │     └─ FilterCommandBar
   │        ├─ LogicModeIndicator
   │        ├─ FilterCommandInput
   │        └─ SaveQueryTemplateAction
   └─ DeckPane
      ├─ DeckSummary
      │  ├─ EditableDeckTitle
      │  ├─ DeckCount
      │  ├─ DeckMetrics
      │  └─ ManaCurve
      ├─ DeckListScrollArea
      │  └─ DeckList
      │     └─ DeckRow × N
      ├─ DeckHoverPreview
```

구현은 화면 컨테이너, 도메인 컴포넌트, 공통 프리미티브의 3단계 구조를 사용한다. `ScrollArea`, 명령형 버튼, 아이콘, 입력, 선택 컨트롤처럼 두 도메인 이상에서 반복되는 요소만 공통 프리미티브 후보로 둔다. 작은 시각 조각을 목적 없이 별도 컴포넌트로 만들지 않는다.

## 3. 기본 레이아웃

- 앱은 전체 가용 높이를 사용하는 단일 캔버스다.
- 전역 탑 커맨드바는 앱 표면에 포함하지 않는다.
- 카드 라이브러리는 좌측, 현재 덱은 우측에 놓는다.
- 패널처럼 떠 있는 카드형 컨테이너를 사용하지 않는다. 영역은 1px 구분선으로 나눈다.
- 라이브러리 툴바와 필터 명령행은 각각 41px 높이다.
- 카드 라이브러리와 덱 목록은 서로 독립적으로 스크롤한다.
- 필터 도크와 덱 액션 바는 목록 스크롤에 따라 사라지지 않는다.
- 페이지 자체에는 가로·세로 스크롤을 만들지 않는다.

## 4. 반응형 계약

기본 글꼴은 16px이며 대상 해상도는 가변 16:9의 720p, 1080p, 1440p다.

### 분할 화면

- 1280px에서 라이브러리 960px, 덱 320px를 사용한다.
- 덱의 일반 최대 폭은 320px다.
- 창이 줄어들 때 덱 폭을 먼저 줄인다.
- 덱 최소 폭은 현재 덱에서 가장 긴 카드명이 생략 없이 보이는 실제 폭으로 계산한다.
- 분할 화면에서는 카드 라이브러리의 카드 3열과 덱 최소 폭을 동시에 보장한다.
- 두 조건을 동시에 만족하지 못하면 분할을 유지하지 않고 단일 패널로 전환한다.

현재 샘플 덱 기준 검증값:

| UI 글꼴 | 덱 최소 폭 | 분할 화면 시작 |
|---|---:|---:|
| 12px | 203px | 784px |
| 16px | 243px | 824px |
| 20px | 282px | 863px |

16px 기준 824px에서는 라이브러리 581px·카드 3열·덱 243px가 보인다. 823px에서는 단일 패널로 전환한다.

### 단일 패널

- 상단에 `카드 라이브러리 / 현재 덱` 전환 탭을 41px 높이로 표시한다.
- 선택된 패널은 앱의 전체 가용 폭을 사용한다.
- 덱 헤더, 덱 목록과 하단 액션도 중앙의 고정 폭 열로 축소하지 않고 전체 폭을 사용한다.
- 선택되지 않은 패널은 레이아웃과 접근성 트리에서 숨긴다.

### 우선적으로 축약되는 정보

- 덱 폭 299px 이하: 마나 커브를 숨기고 덱 요약을 한 열로 바꾼다.
- 덱 폭 239px 이하: 덱 액션 버튼의 아이콘을 숨긴다.
- 화면 폭 1027px 이하: `카드 라이브러리` 제목을 숨긴다.
- 화면 폭 1024px 이하: `템플릿 저장` 아이콘을 숨기고 글자는 유지한다.
- 화면 폭 900px 이하: `비용` 라벨을 숨기고 카드 종류 선택 폭을 줄인다.
- 화면 높이 719px 이하: AND/OR/NOT의 조건 칩 목록을 숨기고 그룹명과 개수는 유지한다.

## 5. 카드 라이브러리

### 빠른 필터

- 비용은 `전체, 0, 1, 2, 3, 4, 5, 6, 7, 8+`를 다중 선택한다.
- 카드 종류는 하나를 선택한다.
- 컨트롤은 툴바에 붙은 정사각형 셀처럼 보이며 버튼 사이의 별도 외부 패딩을 사용하지 않는다.
- 선택 상태는 하단 액센트 선과 명확한 상태값으로 표현한다.

### 카드 그리드

- 기본 카드 폭은 176px이며 128px에서 240px 사이로 조정한다.
- `Ctrl + / -`, 숫자패드 `+ / -`, `Ctrl+휠`로 한 단계씩 조정한다.
- 한 단계마다 한 행의 카드 수가 하나씩 변하는 것을 목표로 한다.
- 카드 타일에는 별도의 텍스트 설명을 붙이지 않는다. 공식 카드 이미지에 포함된 정보만 보인다.
- 좌클릭은 덱 추가다.
- 우클릭은 카드 상세 진입점으로 예약하지만 상세 팝업 설계는 현재 범위 밖이다.
- 결과가 없으면 그리드 안에 `조건에 맞는 카드가 없습니다.`를 표시한다.

## 6. 고급 필터

- 필터 도크는 카드 라이브러리 하단에 고정한다.
- 활성 조건은 AND, OR, NOT 세 그룹으로 동시에 보인다.
- 색상은 AND `#2F6F8F`, OR `#7656A8`, NOT `#B4475E`를 사용한다.
- 입력은 단일 키보드 입력만 사용한다. 드롭다운이나 목록식 조건 편집기는 두지 않는다.
- `Tab`은 AND → OR → NOT 입력 대상을 순환하고 `Shift+Tab`은 역순으로 이동한다.
- `Enter`는 현재 모드에 조건을 추가한다.
- 입력이 비어 있을 때 `Backspace`는 현재 모드의 마지막 조건을 제거한다.
- 조건은 드래그하여 AND, OR, NOT 사이를 이동한다.
- 조건을 더블클릭하면 제거한다.
- `템플릿 저장`은 항상 글자로 식별할 수 있어야 한다.
- 스니펫과 자동완성은 후속 작업이다.

## 7. 덱 패널

### 덱 요약

- 덱 제목만 기본 글꼴보다 한 단계 큰 20px다.
- 덱 제목은 한 줄을 유지하고 하단이 잘리지 않아야 한다.
- 더블클릭 또는 `F2`로 이름을 편집한다.
- `Enter`는 저장, `Escape`는 취소, 포커스 이탈은 저장이다.
- 기본 메트릭은 평균 마나·총 가루 비용을 왼쪽, 하수인·주문 수를 오른쪽에 둔다.
- 마나 커브는 비용 0부터 7+까지의 가로 막대 8개다.
- 덱 분석 기능보다 덱 구성 작업을 우선하므로 좁은 폭에서는 마나 커브가 먼저 사라진다.

### 덱 목록

- 기본 정렬은 마나 비용 오름차순이며 같은 비용은 한국어 카드명 순이다.
- 각 행은 비용, 카드명, 수량 또는 전설 표시를 포함한다.
- 행 사이의 틈을 없애 목록 전체가 하나의 연속된 덩어리처럼 보이게 한다.
- 카드명은 말줄임표로 바꾸지 않는다. 필요한 카드명 폭이 덱의 최소 폭을 결정한다.
- 카드 행 높이는 44px다.
- 크롭 이미지는 원본 243×64px보다 확대하지 않는다.
- 행이 원본보다 넓으면 이미지는 우측 정렬한다.
- 행이 원본보다 좁으면 이미지는 원본 크기를 유지한 채 중앙을 기준으로 잘린다.
- 행 배경은 `#2B2822`, 호버·포커스 배경은 `#353027`이다.
- 아트 오버레이는 왼쪽 `rgba(24,23,19,.46)`, 중앙 `.12`, 오른쪽 `.62`다.
- 텍스트에는 `rgba(0,0,0,.72) 0 1px 2px` 그림자를 유지한다.
- 마우스 호버 또는 키보드 포커스 시 전체 카드 미리보기를 덱 왼쪽에 표시한다.

### 덱 액션

- `덱 분석`과 `덱 코드 복사` 두 명령만 둔다.
- 덱 목록 상단이나 카드 수 옆에 별도 복사 아이콘을 두지 않는다.
- 덱 코드 복사를 1차 액션으로 표현한다.

## 8. 시각 시스템

### 형태와 밀도

- 하나의 심리스 캔버스와 1px hairline을 사용한다.
- 큰 패널 반경과 그림자를 사용하지 않는다.
- 영역 반경은 0, 작은 행·칩·입력에만 0–3px를 허용한다.
- 4px 기반 간격 체계를 사용하되, 명령 바와 목록은 겹치지 않는 범위에서 조인다.
- Lucide 아이콘을 기본으로 사용한다.
- 하스스톤 고유 의미가 필요한 마나와 가루는 전용 이미지 자산을 사용한다.

### 타이포그래피

- 기본 UI 글꼴은 16px다.
- 덱 제목은 20px다.
- 마나 커브는 12px다.
- UI 글꼴은 `CursorGothic` 계열을 우선하고 시스템 폴백을 둔다.
- 데이터 숫자와 조건 표시는 `JetBrains Mono` 계열을 우선한다.
- 위계는 여러 글꼴 크기보다 간격, 굵기와 색 대비로 만든다.

### 핵심 색상

| 토큰 | 라이트 | 다크 |
|---|---|---|
| canvas | `#F7F7F4` | `#1A1612` |
| canvas-soft | `#FAFAF7` | `#201A15` |
| surface | `#FFFFFF` | `#271F19` |
| ink | `#26251E` | `#F4EDE3` |
| body | `#5A5852` | `#D6C9BA` |
| hairline | `#E6E5E0` | `#453A30` |
| primary | `#F54E00` | `#FF7442` |

다크 모드는 Deep Umber 방향을 사용한다. 라이트 모드의 색을 단순 반전하지 않는다.

### 스크롤바

- 카드 라이브러리와 덱 목록은 동일한 `ScrollArea` 시각 계약을 공유한다.
- 두께는 6px이며 트랙은 투명하다.
- 기본 thumb는 현재 글자색 19% 혼합, 호버·포커스 시 48% 혼합이다.
- thumb 최소 높이는 34px다.
- `scrollbar-gutter: stable`로 콘텐츠 폭 이동을 방지한다.

## 9. 접근성과 키보드 계약

- 모든 키보드 조작 요소에 식별 가능한 포커스 표시를 제공한다.
- 카드 라이브러리와 덱 목록은 각각 키보드 포커스를 받을 수 있다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다.
- AND, OR, NOT은 색만으로 구분하지 않고 텍스트 라벨을 항상 함께 표시한다.
- 동적 카운트와 입력 모드는 필요한 범위에서 `aria-live`로 알린다.
- 모션 감소 설정에서는 추가·미리보기 애니메이션을 제거한다.
- 단일 패널 전환 버튼은 현재 선택 상태를 `aria-pressed`로 전달한다.

## 10. 구현 시 보존할 무결성 조건

다음 항목은 후속 컴포넌트 계약 테스트와 Workbench 조합 테스트의 기준이다.

1. 분할 화면에서 카드 라이브러리는 최소 3열이며 덱 카드명은 하나도 잘리지 않는다.
2. 두 조건을 동시에 만족하지 못하면 가로 오버플로 없이 단일 패널로 전환한다.
3. 카드 라이브러리와 덱 목록의 스크롤 위치는 서로 독립적이다.
4. 필터 명령행과 덱 액션 바는 목록 스크롤 후에도 보인다.
5. 덱 카드 행은 비용·한국어 카드명 순으로 안정 정렬된다.
6. 덱 제목, 카드명과 하단 명령은 대상 글꼴 크기 12–20px에서 겹치지 않는다.
7. 720p 높이에서 하단 필터와 덱 액션이 잘리지 않는다.
8. 키보드만으로 필터 모드 전환, 조건 추가·삭제, 덱 이름 편집과 패널 전환이 가능하다.
9. 장식 이미지 로딩 실패가 비용·이름·수량 텍스트의 판독을 막지 않는다.
10. 콘솔 오류와 페이지 단위 가로 스크롤이 없어야 한다.

## 11. 현재 범위 밖

- 카드 상세 팝업의 정보 구조, 포커스 트랩과 작은 화면 스크롤
- 카드 효과 의미 분석, 관련 카드, 생성 카드와 시너지 탐색 화면
- 쿼리 스니펫, 자동완성과 템플릿 관리 화면
- 덱 분석 상세 화면과 고급 통계
- 데이터 동기화, DB, API 클라이언트와 Tauri IPC
- 로딩·네트워크 오류·부분 동기화 상태의 최종 시각 표현

## 12. 후속 컴포넌트 설계 세션의 산출물

다음 세션은 이 문서의 화면 구조를 변경하지 않고 각 컴포넌트에 대해 아래 항목을 확정한다.

- 책임과 비책임
- 입력 props와 출력 events
- 상태 소유자와 파생 상태
- 기본·빈 상태·오류·비활성·포커스·드래그 상태
- DOM, 접근성, 반응형 불변조건
