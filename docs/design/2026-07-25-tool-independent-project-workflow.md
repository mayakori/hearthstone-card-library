# 도구 독립형 프로젝트 워크플로 전환 설계

## 목표

앞으로 이 저장소에서 수행하는 제품 설계, 구현, 조사, QA, 리뷰와 배포 작업에서 GStack 명령과 스킬을 사용하지 않는다. 기존에 승인된 설계와 과거 계획·보고서는 변경하지 않고 기록으로 보존한다.

## 적용 범위

활성 작업 지침과 현재 진행 중인 UI 설계의 후속 작업 안내만 변경한다.

- `AGENTS.md`
  - `Product Design Workflow`를 도구 독립형 절차로 교체한다.
  - GStack 명령과 스킬을 이 프로젝트에서 사용하지 않는다는 금지 규칙을 명시한다.
  - 기존의 설계 승인 게이트와 `docs/design/` 문서화 원칙은 유지한다.
- `CLAUDE.md`
  - GStack 명령으로 연결하는 `Skill routing` 목록 전체를 제거한다.
  - 설계, 조사, QA, 리뷰와 배포는 `AGENTS.md`와 저장소 기본 명령에 따라 수행하도록 안내한다.
  - GStack 명령과 스킬을 호출하지 않는다는 규칙을 명시한다.
- `docs/handoff-ui-design.md`
  - 기존 UI 설계 결정과 제한은 보존한다.
  - 향후 실행을 지시하는 `GStack 사용` 단락만 일반 설계 검토 절차로 교체한다.

## 도구 독립형 설계 절차

제품 방향이나 UI를 구체화할 때 다음 순서를 따른다.

1. 제품 전제, 핵심 사용자 문제와 성공 기준을 확인한다.
2. 결과에 영향을 주는 선택에는 2~3개 대안과 장단점, 추천안을 제시한다.
3. 화면 구조, 상태 소유권, 상호작용, 반응형과 접근성 계약을 검토한다.
4. 시각 언어를 변경해야 할 때만 사용자 승인을 받고 대안을 만든다.
5. 결정 결과를 `docs/design/` 아래에 기록한다.
6. 사용자가 설계를 승인하기 전에는 런타임 코드나 구현 설정을 수정하지 않는다.
7. 승인 후 별도 구현 작업에서 코드 작성과 검증을 수행한다.

조사, 버그 분석, QA, 코드 리뷰와 배포도 특정 스킬 이름에 연결하지 않는다. 각 작업은 저장소에 정의된 아키텍처 경계, 테스트 명령, Git 규칙과 완료 조건을 직접 따른다.

## 보존 범위

다음 항목은 변경하거나 삭제하지 않는다.

- `docs/design/`의 기존 설계 문서
- `docs/superpowers/`의 기존 계획, 명세와 감사 보고서
- 과거 결정을 설명하는 GStack 언급
- 로컬 `.gstack/` 디렉터리
- `.gitignore`의 `.gstack/` 항목
- `src/`, `src-tauri/`, `package.json`을 포함한 런타임 코드와 설정
- `docs/TODO.md`, `docs/DONE.md`, `docs/kanban.html`

과거 기록의 GStack 언급은 당시 작업 맥락으로만 취급하며, 앞으로 따라야 하는 지침으로 해석하지 않는다.

## 검증

변경 후 다음을 확인한다.

1. `AGENTS.md`와 `CLAUDE.md`에 GStack 사용을 지시하는 문장이 없다.
2. `CLAUDE.md`에 `/office-hours`, `/plan-ceo-review`, `/plan-design-review`, `/design-consultation`, `/design-shotgun`, `/plan-eng-review`, `/investigate`, `/qa`, `/qa-only`, `/review`, `/ship` 호출 지시가 없다.
3. `docs/handoff-ui-design.md`의 향후 단계가 특정 GStack 명령 없이 실행 가능하다.
4. 과거 설계·계획 문서와 로컬 `.gstack/`은 그대로 남아 있다.
5. `git diff --check`와 `npm run check`가 통과한다.

## 완료 조건

- 향후 작업자가 읽는 활성 지침에 GStack 사용 금지와 도구 독립형 절차가 명확하다.
- 현재 진행 중인 HCL-005의 다음 설계 단계가 GStack 없이 진행될 수 있다.
- 과거 문서, 사용자 변경사항, 런타임 코드와 프로젝트 추적 문서에는 변경이 없다.
