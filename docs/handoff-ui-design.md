# UI 구체화 작업 핸드오프

아래 프롬프트를 프로젝트를 연 새 작업에 전달한다.

```text
작업 루트:
C:\Users\main\Desktop\claude_project\hearthstone-card-library

이 프로젝트의 기본 UI와 사용자 흐름을 기초 단계부터 구체화하라.

먼저 다음 파일을 읽는다.

- AGENTS.md
- CLAUDE.md
- README.md
- docs/superpowers/specs/2026-07-16-hearthstone-card-library-bootstrap-design.md
- docs/superpowers/specs/2026-07-16-offline-card-preview-design.md
- preview/cards.html
- data/fixtures/official-card-details.ko-KR.sample.json

이번 작업은 GStack의 제품·디자인 설계 흐름을 사용한다.

- 제품 전제나 사용자의 핵심 문제가 불명확할 때만 /office-hours를 사용한다.
- 화면 구조와 UX 계획은 /plan-design-review로 검토한다.
- 시각적 방향과 디자인 시스템은 레이아웃 승인 후 /design-consultation으로 구체화한다.
- 여러 시각 대안은 사용자 동의가 있을 때만 /design-shotgun으로 만든다.
- 같은 단계에서 GStack과 다른 구현 워크플로를 중복 사용하지 않는다.

중요한 제한:

- 아직 기능을 구현하지 않는다.
- src/, src-tauri/, package.json과 앱 실행 코드를 수정하지 않는다.
- DB, API client, Tauri IPC와 카드 동기화 기능을 작성하지 않는다.
- 설계를 한 번에 확정하지 않는다.
- 중요한 선택마다 2~3개 대안과 추천안을 제시하고 사용자 확인을 받는다.
- 사용자 승인 전에는 다음 단계나 구현으로 넘어가지 않는다.

제품 목표:

하스스톤의 제한적인 인게임 검색과 덱 편집기를 보완하는 개인용 데스크톱 덱 시뮬레이터를 만든다. 전체 카드 라이브러리를 탐색하고, 단순 속성뿐 아니라 카드 효과 의미, 중첩 AND/OR 조건, 관련 카드, 시너지, 카드풀과 버킷을 이용해 카드를 찾는다. 선택한 카드로 덱을 구성하고 최종적으로 하스스톤 덱 코드로 내보낸다.

다음 순서로 단계별 진행한다.

1. 제품 이해와 핵심 사용자 작업 확인
2. 카드 탐색부터 덱 코드 내보내기까지의 핵심 사용자 흐름
3. 데스크톱 화면 구조 2~3개 비교
4. 기본 검색과 고급 AND/OR 필터 UX
5. 카드 상세, 관련 카드, 시너지와 카드풀 탐색
6. 덱 편집, 유효성, 통계와 덱 코드 흐름
7. 선택된 레이아웃의 텍스트 와이어프레임
8. 시각 시스템과 후속 mockup 범위

첫 응답에서는 다음만 수행한다.

- 프로젝트 파일을 읽고 현재 상태를 확인한다.
- 이 앱이 해결하는 문제를 5~10줄로 요약한다.
- 가장 중요한 사용자 작업을 우선순위순으로 제시한다.
- 잘못 이해한 부분이 없는지 사용자에게 확인한다.

첫 응답에서 와이어프레임, 구현 계획 또는 코드를 만들지 않는다.

충분히 논의되고 사용자가 승인한 내용만 docs/design/ 아래의 하나의 간결한 설계 문서로 저장한다. 승인된 문서가 이후 구현의 기준이 된다.
```
